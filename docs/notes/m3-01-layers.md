# M3-01 数仓、业务库与分层

## 1. 数仓为什么存在

业务数据库和数据仓库都在存数据，但服务的动作不同。业务数据库支持“正在办一件事”：创建订单、修改地址、更新支付状态。它强调事务、并发和当前状态正确，常按业务流程频繁增删改。数仓支持“回看一群事”：比较不同城市的订单趋势、复盘商家履约、观察用户复购。它强调大批量读取、跨来源整合和历史可分析。

因此，不能把业务库表原样搬过来就称建模完成。业务库里的 `status = delivered` 只告诉你订单现在已完成；分析还可能需要知道它何时下单、何时被接单、昨天处于什么状态。数仓要保留历史，并把不同来源的编码、时间和口径整理成可共同分析的数据。

一句话区分：**业务库让业务正确运行，数仓让业务可以被稳定地度量。**“读多写少、面向主题、保留历史”都是由这个目的推出来的，而不是背出来的标签。

## 2. 为什么分层

假设每张报表都直接读取订单库、支付库和骑手库，各自清洗状态、关联商家、计算金额，会出现四类问题：

1. **重复建设**：同一套清洗逻辑写十遍，口径迟早分叉。
2. **源系统传染下游**：业务库改一个字段，所有报表同时修改。
3. **故障难定位**：金额不对时，无法判断是源数据、清洗、关联还是报表计算出了问题。
4. **历史难重放**：源系统覆盖当前值后，下游又拿不到当时状态。

分层的本质是把“接入、清洗、公共汇总、场景使用”这些变化速度不同的工作拆开。每层只承担有限职责，既复用前一层成果，也给排查和重跑留下边界。分层不是越多越好；团队很小、任务很少时，过多小表反而增加调度与存储成本。

## 3. 各层放什么

```mermaid
flowchart LR
    src["订单、支付、商家等业务库"] --> ods["ODS 原始层"]
    ods --> dwd["DWD 明细层"]
    ods --> dim["DIM 公共维度层"]
    dwd --> dws["DWS 公共汇总层"]
    dim --> dws
    dws --> ads["ADS 应用层"]
    ads --> bi["报表、分析与数据产品"]
```

- **ODS（原始数据层）**：尽量保留源系统原貌，同时补充接入时间、来源、批次等审计信息。它的核心价值是隔离源系统并保留重放依据，而不是急着做成报表。
- **DWD（明细数据层）**：完成清洗、编码统一、无效记录处理和必要关联，保存最细业务明细。例如声明“一行代表一个订单中的一件商品”，之后所有金额计算都遵守这个粒度。
- **DWS（公共汇总层）**：围绕共同分析对象和周期做可复用汇总，如“一行代表某商家某一天”，沉淀订单量、实收金额、履约时长等公共指标。
- **ADS（应用数据层）**：直接服务某个报表或产品，按场景组织字段和展示口径。它可以用较宽、较扁的结构换取取用方便，但不应重新定义公共指标。
- **DIM（维度层）**：沉淀商家、用户、商品、日期等一致描述，回答“从什么角度看”。它是横向复用的公共资产，并非只能夹在固定两层之间。

## 4. 用外卖订单串起来

一笔订单包含两件商品。ODS 保存接入时的订单、支付和商家记录；DWD 将状态码统一，把订单展开为订单商品明细，并保留订单实付等口径明确的度量；DIM 提供商家所属城市、品类等描述；DWS 汇总商家日订单量与销售额；ADS 为运营看板准备“城市—品类—商家”的排行。

如果运营临时需要“昨日取消率”，不应再从 ODS 写一条绕过全链路的 SQL，而应判断分子、分母是否已有公共定义，在 DWS 补充可复用指标，再由 ADS 展示。这样换一个看板仍能得到同一答案。

不分层的直接后果不是“少了几张表”，而是**业务语义散落在任务里，数据失去共同契约**。分层的收益也不是天然发生：必须同时明确每表粒度、负责人、调度依赖和指标口径，否则只是把混乱复制到更多层。

落地时还要防止“跨层抄近路”。例如 ADS 为赶需求直接读取 ODS，短期少做一次加工，长期却绕过了公共清洗，之后同一报表就会与 DWS 口径不同。允许例外时，也应记录原因、责任人和回收时间。另一个常见误区是每层只做机械复制：如果 DWD 没有统一业务语义、DWS 没有形成公共粒度，表名虽然规范，分层仍没有产生复用价值。判断一层是否必要，就看它是否提供了独立且稳定的契约。

## 口述追问

1. 你说数仓保留历史，是否意味着业务库一定没有历史表？这个判断真正的边界是什么？
2. 如果只在 ODS 和 ADS 之间保留一层，你会先保留 DWD 还是 DWS？为什么？
3. 商家名称已存在于 ODS，为什么还要建设 DIM？直接每次关联 ODS 会有什么后果？
4. 数据量很小时，不分层也能跑通。你会依据哪些信号决定开始补层，而不是为了规范而分层？
5. 某个 ADS 指标被质疑，如何利用分层定位是源数据、业务口径还是汇总逻辑的问题？
