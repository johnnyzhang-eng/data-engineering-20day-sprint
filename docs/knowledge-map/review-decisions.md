# 方法论审阅决定

2026-11-25，仍在方案阶段。依据是用户带回的 Claude Opus 5 审阅（模型版本由用户确认）、Kimi K3.1 Pro 的独立复核及既有多模型意见和本次核对的原条款。

| 审阅意见 | 依据与处理 |
| --- | --- |
| 早点用新岗位挑战设计 | 采纳。M02 同步策划挑战和最终留出，先用挑战集找模板漏洞。用过的样本进入已见回归集 |
| M07 要先对准能力 | 旧 SQLite 反例可独立复跑。新的岗位案例须先确定原条款及具体能力目标。已复现相同总额掩盖订单重复和遗漏 |
| 写清每个工单怎样过关和何时停止 | 采纳。把模型回包、引用一致性、覆盖、可跑性和独立验证分开记 |

| 把近期技术直接纳入 Sprint | 现有证据支持按岗位和深度纳入。J4-03 的 Fluss/Paimon 是引擎研发职责。J4-05 的 Iceberg 等是优先项目经验，Code Agent 写在技能要求。J4-08 的向量数据库/RAG 是加分项，Text-to-SQL 也出现在工作探索。尚未取得仓库外的新 JD 原文，不能据此声称 2026 市场普遍性 |
| 17 份与 20 份岗位，以及面经样本 | 用各自的日期和分母。面经支持练习设计，岗位原文支持职位门槛和职责 |

## Kimi 对修订方案的复核

Kimi 收到两组样本的方案和公开基线摘要，未收到 Claude 的正文。它提出封存公司/模板近似簇、开封前冻结判据及数据漂移时保留 ID 映射。已据此写入任务书。工作初期用逐项核验和少量反例发现问题，样本设计充足后再汇总精确率、召回率等指标。

本轮不再安排 Opus 5.5 重新审整份计划。若新 JD、原文或测试出现影响工单走向且暂无法裁定的分歧，再针对同一证据包请第三方复核。
