# 数据工程知识地图建设任务书

**状态：方案待确认。** 本 PR 交付方法、工单、协作方式和已有小样。新岗位采集、课程扩写和批量建图在方案确认后启动。

## 目标与范围

面向数据开发、数仓和数据工程求职，建立一张可以从岗位或工程问题进入的学习地图。学习者能看到工作全貌、先修关系、适用材料和掌握标准。地图也要讲清计算机基础、AI 发展与 agent、怎样高效使用模型并验证代码。20 天 Sprint 是其中一条求职路线。

用 Markdown 节点和稳定 ID 保留三种关系。**前置**说明先懂什么，**应用**指向工程任务和故障，**历史**说明当时的问题、方法和局限。将来若做可视化，用同一批节点生成浏览入口。地图覆盖依赖来源、深度、材料和可复做的验证，个人掌握另看独立操作、解释和未见变式。

## 方法论

### 验证每一段链路

1. **抽取忠实。** 给岗位和条款分配稳定 ID，保留原文定位、快照和日期。区分技能硬要求、职责、加分、任选组和资格。复合条款拆成可单独检查的子项并保留母条款。若资格或软技能不映射到技术课，记录处置。
2. **能力拆分无损。** 给能力分配稳定 ID，保留原条款的目标深度、适用方向与来源。关键硬要求即使低频，也必须在该岗位清单标为已覆盖或缺口。保留任选关系。题频指导练习量，求职优先级还要看实际岗位。
3. **先修关系有根据。** 教材或工程实践推导出的前置单列依据。区分先学才能做和能做以后值得补。
4. **材料真的讲到目标。** 核课程章节、原著、官方文档或一手研究，写明实际内容和先修。视频定位到讲次、章节或可核实的时间段，阅读定位到小节，练习标明环境。
5. **验收能拒绝错答。** 先冻结输入、独立预期与失败判据，再实际运行。在订单例里同时比对总额、订单 ID 唯一性和逐行结果。概念题也要有可判断的解释标准。分别记录模型回包、结构校验、独立复核、实际执行和缺口。

### 早期挑战与最终留出

- **建图集**由旧样本与明确归入建图的新材料组成。冻结来源版本和条款清单。
- **挑战集**用于小样后的早期压力测试，按岗位类型去重，优先选技术栈或能力深度不同的岗位。允许根据结果回改模板。用过即属于已见数据。
- **最终留出集**同步策划，由独立验收者封存正文或快照，仅公布分布和状态。按公司、岗位 ID、转贴和近似 JD 去重。最终检验后若用其中实例修图，该实例转为已见回归样本，下轮用新的留出数据。

首轮计划覆盖数仓／数据开发、偏实时或湖仓工程、数据平台／引擎对照。规模和资格按实际取得的独立原文记录。用少量样本发现断点，保留尚缺的类别。市场流行度需要新证据进一步核实。

### 最终留出验收协议

独立验收者在早期挑战前封存最终留出集的来源、去重分组、取得日期及快照哈希。公开 Issue 只记录封存状态与分布；建设者在开封前看不到正文。若原文不能合法保存，记可回查定位和访问状态。

建图者在开封前冻结编码口径、能力定义、验收用例、缺口处置和通过判据。验收者先按原文建立独立的预期条款与要求类别，再比对遗漏、错误归因、深度、选项关系以及证据链。小批报告逐条结果，样本设计足够时再汇总指标。参考答案应通过，已知错误答案应失败，同一输入重复运行时结果应稳定。历史节点另对照原文验证时间和因果，agent 案例另核工具执行与故障反馈。

开封后只评、只记结果。若发现泄漏、近似重复或临时改规则，标记本轮独立性失效。如果用结果改图，原留出集保留为回归样本，另取新集再做独立验收。最终留出测试检验岗位映射的迁移能力；个人学习效果仍看独立作答与实跑。

| M03 岗位映射 | 节点整理者，M01 和公开条款 | 先用 J4-01 做单条链路，再逐项给整份 JD 标覆盖、缺口或非技术处置，之后才做批次映射 | 错引、漏关键硬要求、职责升格、任选关系丢失时退回修复 | M01；扩批须过早期挑战 |
| M04 数据工程专题 | 课程整理者，M03 与已有讲义、官网和教材 | SQL、建表、数仓、Python、管道、调度、质量、性能、批流、治理节点，绑定材料和验收 | 材料或颗粒度不符就退回。证据只够认识层时保留浅节点 | M03 试点、早期挑战、主题来源 |
| M05 计算机基础 | 课程整理者，CS50、数据库课和工程场景 | 从 CSV 编码、程序执行、索引、事务、进程、网络等问题找到讲次与先修 | 找不到合适材料时标缺口，讲次对不上就更换 | 小样无；扩批须复核 |
| M06 AI 史与 agent | 资料整理者，原论文、作者讲义、工程文档 | 时间轴写出当时问题、方法、证据和局限，关联检索、工具、反馈和评估 | 后见动机标推断，年代或因果冲突待核 | 小样无；扩批须复核 |
| M07 验证案例与用模 | 独立验证者，合成样例和冻结的能力目标 | 复跑旧例，新增案例给出独立预期、反例与实测。模型对照记录正确率、返工、用量和耗时 | 错答通过、测试验错能力、模型未执行工具却声称成功时回退 | 旧例可先跑；新岗位案例等 M03 条款及 M04 对应能力确认 |
| M08 学习导航与材料 | 教学整理者，已核对的节点和材料 | 各路径能从实际问题进入，能选视频、书、陪练或实跑分支。长视频标明片段和看完可做的事 | 初学者找不到下一步就改导航，核心缺口保持可见 | 对应 M04–M07 节点 |
| M09 终验与交付 | 独立验收者，M02 封存批次及未见变式 | 按岗位逐条对照，复跑案例，核链接和来源，报告可验证覆盖与缺口 | 关键样本泄漏或指标误判时停止验收，回到出错工单 | M02 最终留出及 M08 |

### 按什么顺序开工

| 阶段 | 并行与串行 | 进入下一阶段的依据 |
| --- | --- | --- |
| 1. 小样与早期挑战 | M01、M02、M05、M06 可并行。M07 可复跑旧例。M01 后做 M03 小样，立即用挑战集核对 | 至少一条岗位链路能追到实跑结果。复合条款与反例能抓错。Transformer 或 ReAct 至少有一张能据原文复核的历史卡。关键缺口有明确处置 |
| 2. 按主题扩批 | 早期挑战过后扩 M03–M06。能力目标确认后扩写对应 M07。M08 随已验收节点接入 | 定向反例与抽查通过。系统性漏项退回模板，记录修改与重测 |
| 3. 最终留出验收 | M09 独立核对冻结版本。回改后用新的未见样本复核 | 关键硬要求逐条有出处和处置，引用的案例可实跑，时间轴因果可追溯，缺口公开列出。个人表现另计 |

湖仓表格式、实时数仓、向量检索和代码 agent 先按岗位与原始资料放到对应分支，标清应认识、理解还是能做。新证据支持更深要求时，再纳入相应路线。每个工单启动时明确负责人、输入版本、文件范围和独立验收者。
